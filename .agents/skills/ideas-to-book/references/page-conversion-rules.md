# Page Conversion Rules (ideas-to-book v2.1)

## Overview

`book-render.mjs` converts each parsed page from the idea manifest into a `<section class="sheet bb">` in the interior HTML file (`books/<slug>/<slug>.html`). This document defines the exact mapping.

---

## Page Section Structure

Every output page follows this anatomy (from `block` skill):

```html
<section class="sheet bb">
  <h2 class="sr">Screen-reader title</h2>
  <div class="tab" style="background:#SECTION_COLOR"></div>
  <div class="top">
    <div class="eyebrow"><b>STEAM-IE</b> · No. DD</div>
    <span class="pill">Section Name</span>
  </div>
  <h1 class="title">Page Title</h1>
  <div class="sub">Subtitle</div>
  <hr class="rule">
  <div class="diagram">         ← BAND: one diagram OR one photo
    <!-- inline SVG diagram -->  OR  <figure class="photo"><img ...></figure>
  </div>
  <hr class="rule">
  <div class="explain">         ← Body copy
    <p>Let's say…</p>
    <p>The real cost…</p>
    <p class="close">The closer.</p>
  </div>
  <div class="ask">             ← Action box
    <span class="lbl">LABEL</span>
    <p>Action content</p>
  </div>
  <div class="foot"><span class="brand">...</span><span class="pg"></span><span class="series">...</span></div>
</section>
```

---

## Markdown → HTML Mapping Table

| Idea File Content | Generated HTML | Notes |
|-------------------|----------------|-------|
| `# STEAM-IE · No. 01 Science` | `<div class="eyebrow"><b>STEAM-IE</b> · No. 01</div>` + `<span class="pill">Science</span>` | Eyebrow number runs sequentially through whole book (not per part) |
| `## Page Title` | `<h1 class="title">Page Title</h1>` | Required |
| `#### Subtitle` | `<div class="sub">Subtitle</div>` | Optional; empty `<div class="sub"></div>` if missing |
| Body paragraphs (markdown) | `<div class="explain"><p>…</p>…<p class="close">…</p></div>` | Last `<p>` gets `class="close"`; markdown rendered via `marked` |
| `[ACTION CALLOUT: LABEL] Content` | `<div class="ask"><span class="lbl">LABEL</span><p>Content</p></div>` | Required |
| `![AI Image Prompt: ...]` | See **Image Classification** below | Prompt extracted, stored in `images/<slug>.txt`; NOT shown in book |
| Page number (from heading) | Preserved in manifest; used for `<span class="pg"></span>` counter | CSS counter increments per sheet |

## Image Classification (Critical)

**Before rendering**, each page is classified as `photo` or `diagram`:

### Classification Rules (hard-coded)

| Type | Keywords in Prompt | Example Subjects |
|------|-------------------|------------------|
| **photo** | `photograph`, `photo of`, `image of`, `picture of`, `shot`, `real`, `physical`, `actual` | fruit, plant, vegetable, tool, equipment, building, construction, cabinet, tray, panel, device, finished product, harvest, person working |
| **diagram** | `diagram`, `schematic`, `chart`, `graph`, `flow`, `process`, `system`, `architecture`, `vector`, `blueprint`, `before`, `after`, `comparison`, `cross-section`, `business model`, `network` | process, airflow, heat transfer, equation, system architecture, before/after, vector illustration, technical drawing |

**Heuristic fallback:** If prompt mentions physical objects (fruit, plant, tool, cabinet, tray, panel, device) → `photo`. Otherwise → `diagram`.

### HTML Output by Type

#### Photo (physical subject)
```html
<div class="diagram">
  <figure class="photo">
    <img src="images/moisture-equilibrium.png" alt="Moisture Equilibrium" width="800" height="600">
  </figure>
</div>
```
- Image generated by `gen-image.mjs` from prompt file
- `preserveAspectRatio="xMidYMid meet"` (no cropping)
- Prompt file saved alongside: `images/moisture-equilibrium.txt`

#### Diagram (mechanism/process)

## Citation Handling

Citations `[cite: N]` in body markdown are transformed per user choice at **Gate 3**:

| Style | Transformation |
|-------|----------------|
| `preserve` (default) | Kept as literal `[cite: N]` in HTML |
| `footnotes` | Replaced with `<sup class="cite">[N]</sup>`; footnotes section **not yet implemented** |
| `references` | Replaced with `<sup class="cite">[N]</sup>`; references page **not yet implemented** |
| `remove` | Stripped entirely |

**Current implementation:** Only `preserve` and `remove` are fully functional. `footnotes`/`references` render `<sup class="cite">` but lack the corresponding notes section/page.

## Colour Roles (from `studio.css`)

The `<div class="tab">` background colour is determined by section:

| Section | Eyebrow | Tab Colour | Hex |
|---------|---------|------------|-----|
| Science | S | Indigo-red | `#e61358` |
| Technology | T | Orange | `#ed7d1f` |
| Engineering | E | Green | `#a0c82f` |
| Arts | A | Teal | `#32b5d3` |
| Mathematics | M | Purple | `#b44b97` |
| Innovation | I | Dark teal | `#306a50` |
| Entrepreneurship | IE | Indigo | `#5441ff` |

**Emphasis spans in explainer:**
- `.bad` — red (`#DC2626`) — threat, mistake, pain
- `.hl` — indigo (`#6366F1`) — mechanism, key idea
- `.good` — teal (`#0D9488`) — good outcome, solution
- `strong` — neutral bold — key phrase
- `.close` on last paragraph — closer line

## Footer Values

| Span | Source | Default |
|------|--------|---------|
| `.brand` | `book.json` → `footer.brand` or `brand` | `yoursite.com` |
| `.pg` | CSS counter (`counter-increment: pageno`) | Auto |
| `.series` | `book.json` → `footer.right` or `series` | `STEAM-IE` |

## Screen-Reader Title

```html
<h2 class="sr">Page Title: Subtitle</h2>
```
Combines `h1` + `sub` for accessibility.

---

## Part Dividers (Generated, Not in Idea File)

`build-book.mjs` inserts part dividers between parts (not rendered by `book-render.mjs`). Dividers use:
- Part name → `<h2 class="dv-name">`
- Part eyebrow (S, T, E, A, M, I, IE) → large number
- Part `why` text → `<p class="dv-why">`
- List of page titles in that part

## Complete Example: Rendered Page

Input (idea file):
```markdown
# STEAM-IE · No. 01 Science

## Moisture Equilibrium
#### The physics of drying: water activity, equilibrium relative humidity, and why fruit stops losing water before it's "dry enough."

Drying is not about heat. It is about **vapor pressure difference**. The air around the fruit must be able to accept more water than the fruit holds. That gap is the driving force.

When the air's relative humidity matches the fruit's water activity, drying stops. This is **equilibrium**. For mango at 50 °C, the equilibrium RH is about 18 %. If your dryer air is at 30 % RH, the fruit will dry. If the air cools at night to 60 % RH, the fruit re-absorbs moisture — the cycle reverses.

![AI Image Prompt: Diagram showing water activity curve vs temperature, with equilibrium zones marked, technical illustration style, no text, clean lines]

[ACTION CALLOUT: MEASURE IT TODAY] Weigh 10 g of fresh mango slices every 30 minutes in your dryer. Plot the curve. Note when the weight stops dropping — that is equilibrium.
```

## Validation Rules (from `book-render.mjs`)

- Every page produces exactly one `<section class="sheet bb">`
- Page order matches manifest order (grouped by part)
- Section colours applied correctly
- No inline `<style>` or `@media print` — theme owns layout
- SVG placeholders have explicit `fill` on all `<text>` elements
- Photo `<img>` has `width`/`height` attributes (no layout shift)
